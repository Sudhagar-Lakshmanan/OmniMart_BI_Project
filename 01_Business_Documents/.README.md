# Business Documents Overview

This folder contains the foundational documents that define the scope, objectives, and requirements of the **"Omnichannel Retail Behaviour and Performance Analytics Dashboard"** project. These artifacts capture the business context, requirements, and structured functional specifications that guide dashboard development.

---

## 1. Sample Business Request Email  
**File:** [Business Request Email](1_Sample_Business_Request_Email.pdf)  

This is a sample request email used to illustrate the initial stakeholder communication. It outlines business goals, expected deliverables, and timeline expectations.

---

## 2. Business Requirements Document (BRD)  
**Files:**  
- [BRD (PDF)](2_Business_Requirements_Document_(BRD).pdf)  
- [BRD (DOCX)](2_Business_Requirements_Document_(BRD).docx)  

**This is a comprehensive document detailing:**

- Project scope and success criteria  
- Current vs future state process flows  
- KPIs and dashboard metrics  
- Functional and non-functional requirements  
- Role-based access matrix  
- Wireframes and visual references  
- Epics, user stories, and stakeholder mapping  
- Use case overview and actor matrix  
- Risks, assumptions, and dependencies  
- Approval and sign-off section  

**Appendices include:**  
- Business case questions and insights  
- Dashboard wireframes  
- Process flow diagrams  
- Epic and user story tables  
- Use case mapping  

---

## 3. Business Case Questions  
**File:** [Business Case Questions](3_Business_Case_Questions.md)  

This file extracts the **key strategic and analytical questions** from the BRD. These questions serve as the foundation for defining dashboard KPIs and guiding the overall analysis.  

---

## 4. Epics, User Stories & Use Cases  
**File:** [Epics, User Stories & Use Cases](4_Epics_UserStories_UseCases.md)  

This file organizes functional requirements into structured sections:  
- **Epics** - High-level business objectives.  
- **User Stories** - Detailed user needs with acceptance criteria.  
- **Use Cases** - System interactions and user flows mapped to dashboard sections.  

This breakdown ensures **traceability** from business needs → user expectations → implemented dashboard features.
